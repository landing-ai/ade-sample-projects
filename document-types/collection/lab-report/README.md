# Lab report

Source assets for `landing.ai/document-type/lab-report`.

## Sample document

`source/labsmart-cbc-sample.pdf` — a **Complete Blood Count (CBC) report** generated by
LabSmart's laboratory information system on its "Labsmart Software Sample Letterhead".
**2 pages, portrait**, a native PDF with a text layer: a patient and sample header with a
barcode and a QR code, a 13-row haematology results table with abnormal values flagged
`L` or `H` and set in bold, a clinical-notes panel, and two signature blocks. Page 2
repeats the header and closes the report.

LabSmart links this PDF from its [CBC report format](https://www.labsmartlis.com/cbc-report-format)
page as an example of what its software prints. It is a vendor specimen: the lab's phone,
email and website are placeholders (`+91 12345 67890`, `yourlabname@gmail.com`,
`yourlabname.in`), the registration number is printed masked, both signatures carry a
"SAMPLE" stamp, and the footer reads "NOT VALID FOR MEDICO LEGAL PURPOSE". The patient name
is part of the vendor's sample and is not featured. The file is used unaltered.

**The shared drive's file was not used.** The ADE Documents drive held a different
document under this request (`doc1-lab-reports/demo_labs_cbc_1.pdf`): a branded
diagnostics-lab report with a patient's name, mobile number, visit ID and barcode, nothing
marking it as a sample, and no source. It appeared to be a real patient's report, so the
operator rejected it, and it was neither parsed nor copied into this repo.

## Why this document

The collection's first **lab report**, and a results table where the meaning sits in
small marks rather than in the values:

- **Flags in their own column.** `L` and `H` sit between the test name and the value,
  with the whole row set in bold.
- **Reference ranges as text.** `13 - 17`, `4,800 - 10,800`, `< 2` and `31.5 - 34.5`,
  which the schema splits into numeric low and high bounds.
- **A nested sub-panel.** The differential leucocyte count is an indented group under a
  header row with no value of its own.
- **Regional units.** Platelets in `lakhs/cumm`, an Indian unit (1 lakh = 100,000).

## Featured fields: one flagged result

All on page 1. The request named no fields.

| Field | Value |
|---|---|
| Test | LYMPHOCYTE |
| Result | 18 |
| Unit | % |
| Reference range low | 20.0 |

The reason a lab report is read: a result outside its range. The lymphocyte count of 18 %
is below the 20–40 % reference range, and the report flags it `L`. Only the lower bound is
featured: the two bounds come from the same cell, `20 - 40`, and would draw the same box
twice. The result's box takes in the `L` flag beside the value.

## What it surfaced

**The team schema has no field for the abnormal flag.** The schema is the team's
existing `lab-report-schema.json`, used unchanged. Each test result has a name, category,
date-time, result, unit, method and reference values, but nothing for the `L`/`H` marker
the report prints, so the flag is lost even though the value and range are right.

**Required fields the letterhead does not carry.** `lab_details` requires address lines
and a city, and `report_status` is required at the top level; this sample prints neither.
Extraction returned null with a `nonconformant_output` warning. These are findings about
the schema, recorded here rather than patched.

**A typo in the schema is carried through.** The upper reference bound is
`referecne_high` in the schema, and the extraction faithfully uses that key.

**Open-ended ranges are read sensibly.** Basophils' `< 2` comes back as low 0, high 2. The
high bound grounds `ok`; the inferred 0 grounds `OFF`, since no 0 is printed.

**The lab name is a placeholder, and the extraction knows it only from the URL.** The
letterhead says "Labsmart Software Sample Letterhead"; the extraction names the lab
`yourlabname`, grounded to the placeholder email and website.

**Dates read OFF only by format.** "Reported on : 17/10/2024 04:55 PM" is extracted
correctly and normalised to `2024-10-17 16:55`, so the grounding check flags it.

## Extraction

**23 leaf fields** in the schema: order ID and report status; the patient (name, ID, age,
gender, date of birth); the lab (name, address, city, phone, fax, website); and each test
result with its reference values. All 13 results on the page are extracted, in order, with
their units and ranges. 4 of 5 top-level fields populate; `report_status` is null.

  "https://www.labsmartlis.com/pdf/pathology/cbc-report-format.pdf"
